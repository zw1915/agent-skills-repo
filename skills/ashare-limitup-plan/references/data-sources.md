# 数据层：数据源、限流与降级

这份文档记录数据层的事实与坑，包括实测到的限流行为。
改数据源之前请先读这里，能省掉几次踩坑。

---

## 一、为什么不用 akshare

首选方案本是 `akshare`（社区标准），但实测：

1. **在 Python 3.13 环境下依赖解析失败**（`ResolutionImpossible`），装不上。
2. 它的股票列表依赖东财 `push2.eastmoney.com/api/qt/clist/get`，
   该接口在受限网络环境下会直接断开连接。
3. 数据源一旦变更或限流，只能等上游更新。

于是改为**自建轻量数据层**：只用标准库 `urllib` + `sqlite3`，
**零第三方依赖**。代价是要自己维护解析，收益是完全可控、可审计、可降级。

## 二、数据源矩阵（按优先级）

| 优先级 | 源 | 历史长度 | 字段 | 覆盖 | 现状 |
|---|---|---|---|---|---|
| 1 | **同花顺** `d.10jqka.com.cn` | 按年取，1999 至今 | OHLC + 成交量 + **成交额** + **换手率** | 沪深北 | 稳定，容忍并发 |
| 2 | 新浪 `money.finance.sina.com.cn` | 单次 3000 根 | OHLC + 成交量 | 沪深北 | 高频后会被封（HTTP 456） |
| 3 | 东财 `push2his.eastmoney.com` | 单次全历史 | OHLC + 成交额 + 换手率 + 涨跌幅 | 沪深北 | 限流严，易被封 |

### 同花顺接口（主源）

```
最近约 140 根 + 年份映射：  /v6/line/hs_{code}/00/last.js
指定年份全年：              /v6/line/hs_{code}/00/{yyyy}.js
                            ↑ 这一位是复权标志，必须取 00（不复权）
```

返回是 JSONP，需要剥掉外层 `quotebridge_...(...)`。字段为逗号分隔：

```
日期,开,高,低,收,成交量(股),成交额(元),换手率(%),?,?,?
```

后三位实测恒为空或 0，未使用。`code` 不带市场前缀（北交所也是 `hs_920000` 这种形式）。

#### ⚠️ 最严重的坑：复权标志位必须取 `00`

URL 中间那一位是复权口径，实测：

| 标志 | 口径 | 实测 600519 各年可得根数 |
|---|---|---|
| `00` | **不复权** ✅ 本项目必须用 | 2014=245、2016=244、2018=243……**各年完整** |
| `01` | 前复权 ❌ 曾误用 | 2014=**0**、2016=119、2018 起才完整 |
| `02` | 后复权 | 与 `00` 值不同 |

用错 `01` 会同时踩两个雷：

1. **价格口径错**：涨跌停价按未复权价四舍五入到分算，复权价破坏
   `close == round(preclose × 1.1)` 这个等式；而且绝对价格类因子
   （价格区间、`股价 < 2 元`过滤）在历史区间全部失真。
2. **历史被截断（更隐蔽）**：前复权序列是滚动重算的，同花顺只提供有限起点。
   实测用 `01` 会得到：600519 起始日变成 2016-07-04、000001 只回溯到 2024-01-02、
   688981 整只缺失——**行数看着有几十万，实际每只股票只覆盖近几年**。

自检方法：抓完后看几只老股的起始日期是否等于其真实上市日或 2014-01-02。
`00` 口径下 600519 的 2014-01-02 收盘应为 **125.98 元**（真实历史价）。

**`last.js` 的年份映射是增量更新的关键**：它的 `year` 字段给出
`{年份: 该年交易日数}`，于是能直接知道该股有哪些年的历史，
回填时不必探测、也不会对未上市年份发无效请求。

⚠️ **坑**：`last.js` 用 `year`（**字典**），而 `all.js` 用 `sortYear`（**列表**）。
键名和结构都不同。只读 `sortYear` 会静默拿到空映射，
后果是「历史回填被静默跳过」——数据看着有、其实只有最近 140 根。
这个 bug 实际发生过一次。

⚠️ **坑**：`all.js` 是列式差分编码（`price` 字段是 4 值一组的增量链），
不是明文，逆向成本高。**不要试图用它取全历史**，按年取是正解。

### 新浪（备源）

```
/money.finance.sina.com.cn/quotes_service/api/json_v2.php/CN_MarketData.getKLineData
    ?symbol=sh600000&scale=240&ma=no&datalen=3000
```

`datalen` 上限实测 3000（约 12 年），返回 `day/open/high/low/close/volume`。
**没有成交额和换手率**，成交额由 `volume × (o+h+l+c)/4` 推算，换手率置 NULL。
需要 `Referer: https://finance.sina.com.cn/` 否则 403。

### 东财（备源）

```
/push2his.eastmoney.com/api/qt/stock/kline/get?...&fqt=0&secid=1.600000
```

11 个字段：日期,开,收,高,低,量(手),额(元),振幅,涨跌幅,涨跌额,换手率。
注意**成交量单位是手**（转换为股需 ×100），与新浪/同花顺的「股」不同。

## 三、限流实测（这部分是真实踩出来的）

| 源 | 行为 | 应对 |
|---|---|---|
| 同花顺 | **服务端限速**：16 线程 ~28 req/s（早期实测），但 300 请求规模下 32 线程 11.5 req/s、64 线程 12.9 req/s —— 封顶约 **12~13 req/s**，且线程越多失败越多（300 请求下 32 线程 5 个失败、64 线程 8 个） | 主源，**加线程无用**，耗时由请求数决定 |
| 新浪 | 6 线程短测 8.1 req/s 零失败，但**持续抓取后仍会转 HTTP 456**（实测跑到几百只后单请求也 456）；10 线程立刻降到 2.2 req/s、失败 79 | 只在同花顺失败时降级，**并发 ≤6**，且要接受它会阶段性被封 |
| 东财 | 短时高频后所有 host 都被断连；实测连 10 个串行请求也 100% 失败 | 仅在需要换手率且同花顺不可用时使用 |

**结论**：不要把「高频抓取」写在主路径上。
主路径固定用同花顺，其余源只在失败时兜底。`http_get_text` 内置指数退避重试，
所有抓取必须走它，不允许裸调 `urlopen`。

### 耗时估算（决定全量回填时长的是请求数，不是线程数）

| 任务 | 请求数 | 按 13 req/s 计 |
|---|---|---|
| 全量回填 2014–2026 | 5561 只 × (1 last.js + ~11 年份) ≈ 8 万 | **~100 分钟** |
| 日常增量 | 5561 只 × 1 last.js | **~7 分钟** |

> 想缩短回填时间只有两条路：换数据源（新浪 1 请求/股但缺字段、并发受限），
> 或减少年份。**提高 `--workers` 没有意义**——服务端限速，实测 64 线程不比 32 快。

## 四、字段可用性矩阵（降级时看这个）

| 字段 | 同花顺 | 新浪 | 东财 | 缺失时的处理 |
|---|---|---|---|---|
| OHLC | ✅ | ✅ | ✅ | 必需，缺失即跳过该股 |
| 成交量 | ✅ | ✅ | ✅（手→股） | 量能因子必需 |
| 成交额 | ✅ | 推算 | ✅ | 用推算值，误差很小 |
| 换手率 | ✅ | ❌ | ✅ | 因子按**中性分**处理，不奖不罚 |
| 涨跌幅 | 可算 | 可算 | ✅ | 用 `close/close.shift(1)-1` 自算 |

`strategy.band_score` 对缺失值返回 0.5（中性），
所以换手率缺失不会让某只股票被系统性低估或高估。

## 五、增量更新的设计

```
首次：--years 2014-2026        每只股票 = 1 次 last.js + N 次按年文件
日常：--incremental            每只股票 = 1 次 last.js（约 140 根）
```

**为什么增量只需 1 个请求**：`last.js` 每次返回最近约 140 根日线，
覆盖 7 个月，足够补上任何合理的停机时长。全市场约 3 分钟。

**判断「还缺哪些年」必须用「已入库年份集合」，不能用「最后日期」。**
因为 `last.js` 会让 `last_date` 看起来是最新的，
用最后日期判断会得出「无需回填」的错误结论。
这个 bug 实际发生过一次（见 `update_data.plan_years` 的注释）。

**幂等**：全部走 `INSERT OR REPLACE`，中断后直接重跑即可续上，
重复跑不会产生脏数据。

## 六、新增数据源的步骤

1. 在 `ashare_lib.py` 里加一个 `fetch_kline_xxx()`，
   **返回值统一为 8 元组**：`(date, open, high, low, close, volume股, amount元, turnover%)`。
   缺失字段用 `None`，不要用 0 冒充——0 会被当成真实值参与打分。
2. 在 `SOURCES` 元组里登记名字，并在 `fetch_history()` 里加分支。
3. 若作为主源，注意 `update_data.py` 的增量逻辑依赖「能一次拿到最近 N 根 + 年份清单」，
   不具备这个能力的数据源只能用于回填，不能用于日常增量。
4. 用 `--limit 20` 试跑，检查 `daily` 表的成交额量级是否合理
   （大盘股应在数亿到数十亿之间；若差 100 倍，多半是成交量单位搞错了）。
