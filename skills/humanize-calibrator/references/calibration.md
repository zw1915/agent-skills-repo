# 迭代校准机制（Calibration Loop）

本文件定义：为什么这个技能不是「一次性改写工具」、反馈如何变成资产、以及过改的边界。

---

## 1. 三轮收敛流程

```
第 1 轮  R1 体检 ──→ 改写 ──→ 复检        （全维度处理）
第 2 轮  R2 用户反馈 ──→ 定向修正 ──→ 复检  （只动用户指出的维度）
第 3 轮  R3 再反馈 ──→ 微调 ──→ 交付        （只做局部替换，不改结构）
```

**R1 之后必须停下来问一次。** 不要在用户没看之前连续改三轮——用户的需求往往是
「保留某些东西」，而这个信息只有用户能给。

### 每轮必须回答的三个问题

1. 这一轮改的是哪个维度？（必须说得出编号，如 D2、D6）
2. 改动的依据是清单里的哪一条规则？
3. 有没有可能改坏了？（主动说出风险，让用户判断）

**改不出维度的修改，就是随机润色，不算校准。**

---

## 2. 反馈分类表（收到反馈后先归类，再动手）

用户反馈往往模糊（「感觉还是不对」）。必须先映射到具体维度，否则会陷入无效来回。

| 用户原话 | 映射维度 | 动作 |
|---|---|---|
| 「太正式了 / 太端着」 | D4、D5 | 加人称、加短句、加口语插入 |
| 「太口语了 / 不够专业」 | 过改护栏 | 回退口语化改动，恢复术语与正式句式 |
| 「太长了 / 说不到重点」 | D7 | 删废话率高的句子，先删复述段 |
| 「太简略了 / 没讲清」 | D3 | 补场景，数字不足处开待补清单 |
| 「有点假 / 像在硬夸」 | D2-4、D4 | 删形容词通胀，补代价与边界 |
| 「太平了 / 读不下去」 | D5、D1 | 制造长短句落差，拆掉均匀段落 |
| 「全是套话」 | D2、D6 | 黑话落地 + 删套壳模板 |
| 「不像我写的」 | 语料对齐 | 读校准档案的「语料样本」章节，提取该用户的句式习惯 |
| 「这个不能说 / 要改口径」 | 内容合规 | 按用户口径替换事实表述，不算校准问题但必须照做 |

**若用户的反馈无法归入任何维度**，直接问一句：「你是希望它更短、更具体、
还是更有立场？」三选一，用户通常立刻能答。

## 3. 校准档案（Calibration Profile）

### 位置

```
~/.workbuddy/skills/humanize-calibrator/calibration-profile.md
```

用户级、跨会话、跨项目。**每次开始校准前先读这个文件**；不存在则跳过，
在第一次收到明确反馈后创建。

### 结构

```markdown
# 校准档案

## 基本偏好
- 默认文体：半正式（个人博客腔）
- 口语化程度：中等（允许短句与插入语，禁止网络流行语）
- 篇幅倾向：偏短，能删就删

## 必须保留的词（禁改）
- （行业术语、公司内部用语、品牌名、合规话术）

## 忌讳词（黑名单）
- （用户明确讨厌的词，例如「赋能」「家人们」「绝绝子」）

## 语料样本
- 在这里直接粘贴用户本人写过的原文（2–3 份，合计 800–2000 字），不要放目录
- 已对齐的样本：见下方「反馈日志」上方记录；样本原文可留、可清空

## 反馈日志
| 日期 | 用户反馈 | 映射维度 | 生效的规则调整 |
|---|---|---|---|
| 2026-09-14 | 「太端着了」 | D4/D5 | 默认增加第一人称与短句，减少礼貌收尾 |
| 2026-09-14 | 「不要用赋能」 | D2-1 | 加入黑名单，且不再出现在改写稿中 |
```

### 写入规则

- **只写稳定的偏好**，不要写一次性的、本次任务特有的要求。
- 每次写入都要在「反馈日志」留一行，说明这条偏好是从哪次反馈来的。
- 用户明确说「以后都这样」→ 必须写入；用户只是本次要求 → 不写入，仅本轮生效。
- **不要写敏感的个人信息**。档案只保存写作偏好。

### 读取规则

- 档案里的「黑名单」优先级高于清单中的任何改写手法。
- 档案里的「必留词」在改写中**一个字都不能动**，即使它命中了 D2 黑话词表。
- 档案与清单冲突时，**档案优先**（个性化高于通用规则）。

## 4. 语料对齐（让改写像本人，而不是像另一个人）

当校准档案 `calibration-profile.md` 的「语料样本」章节中存在用户本人的写作样本时
（也可由用户在对话里直接提供）：

1. 提取该用户的可观察习惯，**只提取、不评判**：
   - 平均句长与短句频率
   - 是否常用第一人称、常用哪个（我 / 我们 / 笔者）
   - 标点习惯（是否爱用破折号、括号插入语）
   - 段落长度习惯
   - 常用的口头词（不一定是流行语，可能是「说白了」「本质上」这类个人习惯语）
2. 把这些习惯作为改写的**约束条件**，叠加在清单处方之上。
3. 在报告中说明「已按你的语料样本对齐：句长、人称、标点习惯」。

**语料对齐优先于通用改写处方。** 若用户习惯写长句，就不要为了 D5 分数
硬塞短句——把 D5 的判定口径调整为「相对该用户基线是否有起伏」。

## 5. 过改护栏（Over-rewrite Guardrails）

这是本技能最重要的边界。去 AI 味最常见的失败不是改得不够，而是**改过头**。

### 绝对禁止

| 禁止项 | 原因 |
|---|---|
| 堆 emoji 与网络流行语（「家人们」「绝绝子」「谁懂啊」「冲就完事了」） | 这是表演性口语，信息量为零且可信度更低 |
| 虚构案例、数据、引用、人名 | 校准是改表达，不是编事实。缺失的一律用占位符 |
| 删改数据、结论、观点的方向 | 只改怎么说，不改说什么 |
| 把正式文体改成随笔腔 | 合同、公文、论文、学术摘要保持原有严肃度 |
| 为了刷 HI 而破坏准确性 | 分数服务于表达，不是目的 |
| 批量删除专业术语 | 术语 ≠ 黑话。判定标准是是否携带可验证信息 |

### 需要先询问的情况

- 原文**完全没有**具体细节，而补细节会改变论证 —— 问用户能否提供，不要自行填充
- 用户没说明文体，且文本可能是对外发布物（合同、公告、对外稿）—— 先确认文体
- 用户要求「改得像某个人写的」但提供了他人的文章 —— 只对齐**风格特征**，
  不做风格模仿式的仿写，也不复制其标志性表达

### 自检问句

改写完成后，逐条自问：

1. 我有没有添加原文没有的事实？（有 → 改成占位符）
2. 我有没有改动数字或结论？（有 → 回退）
3. 改写后的文本，作者敢用自己的名字发出去吗？（不敢 → 重改）
4. 删掉了我加的所有「人味」修饰后，文本还站得住吗？（站不住 → 是修辞堆砌，
   不是内容改善）
5. 这次改写是让文本更清楚，还是只是让它更松弛？（只是松弛 → 可能过改）

## 6. 文体契约（Genre Contract）

改写幅度必须服从文体。先判定，再动手。

| 文体 | 允许的改动 | 不允许的改动 |
|---|---|---|
| 营销文案 | 口语化、短句、加场景、加对比 | 删掉承诺性表述、改动价格与效果描述 |
| 公众号 / 博客 | 第一人称、个人观点、适度情绪、口语插入 | 网络流行语堆砌、编造经历 |
| 商业报告 | 具体化数字、删空话、明确结论 | 删小标题编号、改成随笔腔、加第一人称情绪 |
| 学术论文 / 摘要 | 删冗余副词、删套壳过渡、精确措辞 | 动结论、改术语、加个人口语 |
| 公文 / 合同 | 仅做语句通顺与冗余删除 | 任何语义调整、口语化、删礼节用语 |
| 技术文档 | 删形容词、补具体参数、明确适用边界 | 删步骤编号、改成叙述体、模糊化参数 |

判定不出文体时，**默认按商业报告处理**（保守），并在报告开头说明这一假设。

---

## 7. 复检口径一致性

复检必须用与体检完全相同的口径，否则提升是假的。具体做法：

1. 用同一版 `tone_scan.py` 跑 before 与 after（不要中途改词表）。
2. 用同一版 `checklist.md` 打子分（不要因为「已经改过了」而放宽标准）。
3. 在报告里同时列出 before 与 after 的**原始扫描数据**（词频、标准差），
   让人可以核对，而不是只给一个结论性的分数。

> 如果 after 的某个维度分数没提升，如实写出来。**诚实的不完美报告比漂亮的假报告有用。**
