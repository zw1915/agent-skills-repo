# 人味检查清单（Human Index Checklist）

7 个维度，权重合计 100。每个维度打 0–10 子分（10 = 最有人味，0 = 最像机器），
加权求和后除以 10，得到 **人味指数 HI（0–100）**。

```
HI = Σ (维度子分 × 维度权重) / 10
```

## 等级判定

| HI | 等级 | 处置 |
|---|---|---|
| 85–100 | 人味充足 | 只做微调，不要大改 |
| 70–84 | 轻度 AI 味 | 处理得分最低的 1–2 个维度 |
| 50–69 | 明显 AI 味 | 处理 3–4 个维度，结构层可能需要动 |
| 30–49 | 模板化严重 | 建议重构骨架，而非逐句修 |
| 0–29 | 机器腔 | 先确认是否值得保留原文结构，多半要重写 |

---

## D1 · 结构机械度　权重 15

**检测子项**

| 编号 | 特征 | 高危信号 |
|---|---|---|
| D1-1 | 显式序数词 | 「首先/其次/再次/最后」「第一/第二/第三」，尤其是三段以上连用 |
| D1-2 | 总—分—总强迫症 | 开头必点题、结尾必升华，中间必然三点并列 |
| D1-3 | 并列项字数对仗 | 三个小标题字数完全相同、句式完全平行 |
| D1-4 | 段落长度均匀 | 每段 3–4 句、长度高度一致 |
| D1-5 | 标题工整化 | 「××化、××化、××化」「从××到××」式双联标题 |

**打分口径**（起始 10 分，按命中扣）

| 情况 | 子分 |
|---|---|
| 无显式序号，结构随内容起伏 | 9–10 |
| 有 1–2 处套路结构，但整体自然 | 7–8 |
| 多处显式序号 / 段落长度高度均匀 | 4–6 |
| 通篇「首先其次最后」+ 总分手三段式 + 并列对仗 | 0–3 |

**改写处方**

- 拆掉序数词，用**内容本身的逻辑连接**替代：「首先……其次……」→「最直接的原因是……；
  更麻烦的是……」（用语义关系代替编号）
- 允许段落长度悬殊：重点段落 6 句，过渡段落 1 句
- 小标题不必对仗，可以长短不一、甚至只有一两个小节有标题
- 若确实需要清单化（操作步骤、参数列表），**保留编号**——结构化在清单场景是加分项，
  不是 AI 味。见 D1 反例说明

> **反例说明**：操作手册、菜谱、API 参数说明里出现「1. 2. 3.」是正确写法。
> 本维度针对的是**论述性文本里滥用编号来伪装条理**。

## D2 · 词汇空泛度　权重 18

**检测子项**

| 编号 | 特征 | 说明 |
|---|---|---|
| D2-1 | 大厂黑话空转 | 赋能、抓手、闭环、沉淀、对齐、颗粒度、心智、打法、组合拳、底层逻辑、护城河、生态位、拉通、协同、抓手、势能、飞轮 |
| D2-2 | 万能副词 | 极大地、显著地、有效地、充分地、深度地、进一步、持续不断地 |
| D2-3 | 抽象名词堆砌 | 价值、维度、层面、体系、机制、能力、链路、矩阵（无具体指称时） |
| D2-4 | 形容词通胀 | 「非常重要」「极其关键」「核心中的核心」等无法证伪的强调 |
| D2-5 | 同义反复 | 「进一步深化提升」「持续优化改进」——两个词说同一件事 |

**打分口径**

| 情况 | 子分 |
|---|---|
| 用词具体、可指认，无空转黑话 | 9–10 |
| 偶有 1–2 个万能副词 | 7–8 |
| 每 200 字出现 2–4 个空泛词 | 4–6 |
| 每 200 字 5 个以上，或整段由抽象名词构成 | 0–3 |

**改写处方**

- 黑话落地：问「这个词换成一句大白话，信息会少吗？」
  「赋能业务增长」→「让业务部门少花两周时间做数据核对」
- 删掉所有不能证伪的副词。**删完之后如果句子没变弱，说明它本来就不需要**
- 抽象名词必须有具体指称：「提升协同效率」→「把审批从 3 天压到 4 小时」
- 警惕同义反复，直接删一半

> **术语 vs 黑话的判定标准**：该词是否携带可验证信息？
> 「年化波动率」「边际成本」「存续期」是术语，保留；
> 「抓手」「闭环」「势能」在多数语境下不携带信息，替换。
> **不要为了去 AI 味而删掉真正的专业术语，这是过度改写。**

## D3 · 细节具体度　权重 18

**检测子项**

| 编号 | 特征 | 说明 |
|---|---|---|
| D3-1 | 无任何数字 | 全文没有金额、时间、比例、数量、型号 |
| D3-2 | 无专有名词 | 没有人名、地名、公司名、产品名、书名、事件名 |
| D3-3 | 无可复现场景 | 抽象议论，读者无法想象画面 |
| D3-4 | 只有结论没有过程 | 「效率提升了」但不说怎么提升、提升前后各是多少 |
| D3-5 | 举例空转 | 「比如某某企业」「举个例子」却不给具体是谁 |

**打分口径**

| 情况 | 子分 |
|---|---|
| 每 300 字至少 1 个可验证的具体信息，且有场景 | 9–10 |
| 有零星数字/名称，但偏装饰性 | 7–8 |
| 全文 1–2 个具体点，其余抽象 | 4–6 |
| 全篇无数字、无专名、无场景 | 0–3 |

**改写处方**

- **绝不虚构**。原文没有的细节，用 `【待补：请提供××的具体例子】` 占位，
  并在报告末尾列成待补清单交给用户填写
- 把抽象判断改写成**可复现场景**：「用户体验不好」→「点了三次保存都没反应，
  用户会直接关页面」
- 优先保留原文已有的数字，并把它放在显眼位置，不要埋在中段
- 一个真实的小细节胜过三个笼统的形容词

## D4 · 立场与声音　权重 14

**检测子项**

| 编号 | 特征 | 说明 |
|---|---|---|
| D4-1 | 无第一人称视角 | 通篇无人称主语，像说明书 |
| D4-2 | 骑墙不表态 | 「一方面……另一方面……」，但从不给倾向 |
| D4-3 | 无主观判断 | 全是对事实的罗列，没有「我认为」「更值得」 |
| D4-4 | 无情绪波动 | 任何话题都是同一个温度 |
| D4-5 | 过度礼貌收尾 | 「希望对您有所帮助」「如有疑问欢迎交流」 |
| D4-6 | 绝对化的免责腔 | 「具体情况需具体分析」「因人而异」式万金油 |

**打分口径**

| 情况 | 子分 |
|---|---|
| 有清晰立场、可感知的作者存在 | 9–10 |
| 有观点但表达克制、偶有骑墙 | 7–8 |
| 观点模糊，多数段落只陈述不判断 | 4–6 |
| 通篇无立场、无情绪、以客套收尾 | 0–3 |

**改写处方**

- 加入**可追责的判断**：「这值得做」→「如果只能做一件事，我会先做这个」
- 把骑墙句改成**带条件的取舍**：「A 和 B 各有优劣」→「预算够就上 A，
  预算紧就先用 B 顶半年」
- 允许出现一次「说实话」「我原本以为……结果」这类真实反应
- 删掉礼貌性收尾。**结尾不要总结升华，直接停在最后一个具体事实上更有力**
- 注意：删客套 ≠ 无礼。正式文体的礼节性用语按文体契约保留（见 `calibration.md`）

## D5 · 节奏起伏度　权重 12

**检测子项**

| 编号 | 特征 | 判定数据 |
|---|---|---|
| D5-1 | 句长标准差过小 | 标准差 < 8 字 → 节奏平铺 |
| D5-2 | 最长/最短句比值过小 | 比值 < 2.5 → 缺乏起伏 |
| D5-3 | 无短句 | 缺失 10 字以内的句子 |
| D5-4 | 段落长度方差过小 | 所有段落句数接近 |
| D5-5 | 无口语插入 | 全文没有「其实」「话说回来」「这就有点……」等自然插入 |

**打分口径**

| 情况 | 子分 |
|---|---|
| 句长标准差 ≥ 14，有长短句交错 | 9–10 |
| 标准差 8–14，节奏尚可 | 7–8 |
| 标准差 5–8，明显平铺 | 4–6 |
| 标准差 < 5，句子长度像被裁过 | 0–3 |

**改写处方**

- 主动制造**长短交替**：一个 30 字的长句后面，跟一个 4 字的短句。「这就是问题所在。」
- 关键结论用短句独立成段
- 加入 1–2 处口语插入语，但**不要刻意**，也不要密集
- 允许不完整的句子出现在口语化文体里，正式文体禁止

## D6 · 逻辑套壳度　权重 13

**检测子项**

| 编号 | 特征 | 高危模板 |
|---|---|---|
| D6-1 | 背景起手式 | 「随着……的发展」「在……的大背景下」「在当今……的时代」 |
| D6-2 | 万能递进 | 「不仅……而且……」「既……又……」连用 |
| D6-3 | 升华收尾 | 「综上所述」「总而言之」「让我们一起……」 |
| D6-4 | 提示型过渡 | 「值得注意的是」「需要强调的是」「不得不说」 |
| D6-5 | 排比滥用 | 三句以上结构完全相同的排比 |
| D6-6 | 设问自答 | 「那么，××是什么？××就是……」连续使用 |

**打分口径**

| 情况 | 子分 |
|---|---|
| 无套壳模板，逻辑由内容驱动 | 9–10 |
| 偶有 1 处套壳 | 7–8 |
| 出现 3–4 处套壳 | 4–6 |
| 开头升华、结尾升华、中间排比 | 0–3 |

**改写处方**

- 背景起手式 → **直接给最具体的一个事实开头**。
  「随着数字化转型的深入，企业面临……」→「一家 200 人的公司，每个月有 40 小时
  花在手工对账上。」
- 删掉所有提示型过渡词，直接写下一句。**读者不需要被告知「接下来很重要」**
- 结尾升华改为停在一个可执行的动作或一个具体数字上
- 递进关系用内容体现，而不是用「不仅……而且……」硬接

## D7 · 信息增量度　权重 10

**检测子项**

| 编号 | 特征 | 说明 |
|---|---|---|
| D7-1 | 废话率 | 删掉整句后信息零损失的比例 |
| D7-2 | 回避代价 | 只讲好处，不讲成本、风险、失败条件 |
| D7-3 | 复述标题 | 段落反复复述已说过的观点 |
| D7-4 | 正确但无用 | 「要做好规划」「要注重质量」式绝对正确的空话 |
| D7-5 | 无取舍 | 什么都推荐，等于什么都没推荐 |

**打分口径**

| 情况 | 子分 |
|---|---|
| 每段都有新增信息，明确说明代价 | 9–10 |
| 少量重复，代价提及不充分 | 7–8 |
| 约三成内容为复述或空话 | 4–6 |
| 一半以上可整段删除而不损失信息 | 0–3 |

**改写处方**

- 逐句问「删掉它，读者会失去什么？」答案是没有 → 删
- 补上**代价与边界**：「这个方法好用」→「这个方法只适合团队小于 10 人的时候用，
  再大就得换」
- 删除所有复述型段落
- 给出取舍：明确说出「什么情况下不要这么做」

---

## 评分注意事项

1. **先取证据，再打分。** 每个子分都要能指回原文的具体字句。写不出证据就不该扣分。
2. **不要为了分数好看而抬分。** HI 虚高的体检表会让用户失去信任，也失去迭代的价值。
3. **维度之间会联动。** 修掉 D1（结构）与 D6（套壳）通常连带改善 D5（节奏）。
4. **文体契约优先于分数。** 公文、合同、学术摘要里低分是合理的，不要为了刷 HI 破坏文体。
   此时应在报告中说明「本文体下 D1/D4 低分属正常」。
5. **复检必须用同一套口径。** 换口径打出来的提升是假的。
