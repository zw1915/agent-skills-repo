# 内容获取与降级流程（Extraction）

拆解的前提是**拿到原文**。拿不到就如实说明——绝不基于标题和想象输出一份看似
完整的拆解报告。这是本技能最容易失败的地方，也是最容易取信于用户的地方。

---

## 1. 四种输入形态

| 输入 | 处理 |
|---|---|
| **链接** | 先跑 `decode_scan.py --url` 识别平台，再按难度抓取（见第 3 节） |
| **粘贴的文本** | 最佳输入。直接进结构扫描，跳过抓取 |
| **截图** | 用 Read 读取图片提取文字，再进扫描。注意截图常缺首尾，要问用户补 |
| **多条链接对比** | 逐条拆解后增加一层「共同结构」归纳，输出共性骨架 |

---

## 2. 平台识别

```bash
python scripts/decode_scan.py --url "https://..."
```

脚本输出平台的**建议抓取路径**。识别结果包含：

- `平台` 与 `内容形态`（图文 / 短视频 / 中长视频 / 问答 / 音频 / 短图文）
- `抓取难度`（低 / 中 / 高）
- `建议路径`（直接抓取 / 先试后降级 / 直接请用户粘贴）

短链（`t.cn`、`xhslink.com`、`b23.tv`、`v.douyin.com` 等）会先标注需展开再判断。
展开短链属于抓取动作，同样受第 4 节降级规则约束。

---

## 3. 抓取策略分级

### 低难度 —— 直接抓取

| 平台 | 可取内容 |
|---|---|
| B站 | 页面标题、简介、字幕（如有）、评论数 |
| 播客（小宇宙、喜马拉雅等） | 节目简介、show notes、时间轴 |
| 个人博客 / 独立站 | 全文 |
| Newsletter 归档页 | 全文 |

策略：用网页抓取能力直接取正文，成功率高，不需要浏览器自动化。

### 中难度 —— 先试后降级

| 平台 | 情况 |
|---|---|
| 公众号 | 公开文章常可直接访问；可能触发验证页或要求跳转 App |
| 知乎 | 答案多为公开可读；部分内容要求登录、长答案可能截断 |
| 微博 | 公开微博可读；长文可能跳转、评论可能需登录 |

策略：先尝试一次标准抓取。**失败只重试一次**（换移动版地址等），仍失败立刻降级，
不要反复重试同一路径。

### 高难度 —— 直接请用户粘贴

| 平台 | 原因 |
|---|---|
| 小红书 | 强反爬，未登录几乎拿不到正文 |
| 视频号 | 无稳定的公开网页正文，需在微信内查看 |
| 抖音 / 快手 | 需 App 内环境，网页端信息极有限 |

策略：**不要尝试抓取**，直接向用户说明「这个平台拿不到公开正文」，并给出替代方案。
硬试 3 次再失败的体验比一开始就问差得多。

> 若用户环境具备浏览器自动化能力，可以在用户**明确同意**后用于中难度平台。
> 高难度平台仍然建议直接请用户粘贴——登录态内容不适合自动获取。

---

## 4. 失败降级阶梯（按顺序执行）

```
1. 标准网页抓取
   ↓ 失败
2. 换入口：移动版地址 / 归档页 / 缓存页 / 短链展开后重试
   ↓ 失败
3. 请用户粘贴正文
   ↓ 用户不方便
4. 请用户发截图（可多张），用图片读取提取文字
   ↓ 用户也不方便
5. 降级为「局部拆解」：仅基于标题 + 首段 + 可见互动数据
   → 必须在报告开头显著标注：⚠️ 本报告基于局部信息，第 3–5 层无法验证
```

**任何情况下都不要用第 5 节之外的步骤去补全缺失的正文。**
尤其是：不要根据标题推测正文、不要根据同类账号的常见结构「推断」这条的结构。

---

## 5. 拆解所需的最低字段清单

抓取或粘贴后，先核对字段是否齐备。缺哪项就在报告里标为「未获取」。

| 字段 | 用途 | 缺失影响 |
|---|---|---|
| 标题 / 封面文字 | 拆 L1 注意力层 | 无法拆封面标题组合 |
| 正文全文（含分段） | 拆 L3 主体层、L4 情绪层 | 只能做局部拆解 |
| 首句 / 前 3 行原文 | 拆 L2 钩子 | 拆解质量大幅下降 |
| 小标题（如有） | 拆逻辑链 | 无法判断结构原型 |
| 结尾原文 | 拆 L5 引导层、金句 | 无法拆收尾与 CTA |
| 话题标签 | 小红书专用 | 影响流量策略分析 |
| 发布时间 | 判断是否借势热点 | 弱影响 |
| 互动数据（赞藏评转） | 验证「爆款」程度 | 弱影响，但要如实说明无数据 |
| 视频时长 / 音频时长 | 视频与播客类节奏拆解 | 影响节奏分析 |

**注意**：「互动数据」不影响结构拆解本身。没有数据时照样能拆结构，
但要说明「未获取互动数据，因此无法判断该内容是否属于爆款，仅就其结构做拆解」。

---

## 6. 视频与音频类内容的特殊处理

视频/音频没有天然文本，按以下优先级取文本：

1. **平台字幕 / 文字稿**（B站字幕、播客 show notes 与时间轴）
2. **用户提供的转文字结果**（剪映等工具导出的文字稿）
3. **用户口述大意**（只能做粗颗粒结构拆解，需标注）
4. **尽力转录**：若环境具备语音转录能力且用户同意，可对音频转写

拿不到文本时，仍可基于**可见信息**做有限拆解：时长、标题、封面、开场承诺
（若用户能描述）、互动数据、评论区高频词。**必须标注为受限拆解。**

---

## 7. 多链接对比模式的额外步骤

用户一次给多条同类内容时，在逐条拆解之后增加：

1. **共性结构表**：列出每条命中的钩子类型、结构原型、CTA 类型
2. **共性归纳**：找出 3 条以上都出现的模式 → 这是该赛道最稳的结构
3. **差异点**：找出各自不同的处理 → 这是可选择的变量
4. **输出合并模板**：以共性为骨架，差异点为「可选分支」

这一模式的产出往往比单条拆解更有价值，因为它把「偶然」筛成了「规律」。
