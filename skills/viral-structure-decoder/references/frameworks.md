# 跨平台拆解框架库（Frameworks）

## 0. 通用五层模型（所有平台的兜底骨架）

任何平台的爆款内容都能拆成这五层。平台框架只是给这五层换上该平台的关键决策点。

| 层 | 回答的问题 | 拆解时要指出的东西 |
|---|---|---|
| L1 注意力 | 用户凭什么停下来？ | 钩子类型 + 出现位置（第 1 句 / 前 3 秒 / 封面） |
| L2 承诺 | 用户凭什么看下去？ | 给了什么预期（学到 / 共鸣 / 好奇 / 情绪宣泄） |
| L3 主体 | 信息怎么组织？ | 结构原型 + 分段逻辑 + 每段功能 |
| L4 情绪 | 情绪在哪被推高？ | 峰值位置 + 用的手法 |
| L5 引导 | 用户下一步做什么？ | CTA 类型 + 位置 |

**拆解铁律**：每一层都要能说出「在哪个位置」和「为什么这样能起作用」。
「整体很有感染力」这类判断不算拆解结果。

## 1. 小红书 · 封面标题组合 → 正文钩子 → 互动引导

小红书是**双入口分发**：封面图和标题各是一次独立的点击机会，且二者可以不一致
（封面给情绪、标题给利益）。这是它和其他平台最大的结构差异。

### 1.1 封面标题组合

**封面类型**（观察：用了哪种视觉策略）

| 类型 | 特征 | 适用 |
|---|---|---|
| 大字报 | 纯文字 + 强对比底色，字占画面 1/3 以上 | 观点、清单、干货 |
| 对比图 | 前后 / 左右 / 好坏对照 | 效果类（护肤、装修、改造） |
| 清单图 | 数字 + 多个条目排布 | 干货合集、攻略 |
| 人物出镜 | 真人脸 + 文字贴片 | 人设型账号 |
| 截图/实拍 | 原始界面或生活场景 | 教程、真实感优先 |

**标题公式**（拆解时必须标出命中了哪几个成分）

```
人群词 + 时间/成本 + 获得结果 + 情绪钩子
例：打工人 / 3 天 / 搞定周报自动化 / 亲测有效
```

**判定问题**：标题有没有同时给出「谁能用」「要花多少」「能得到什么」？
三者缺一，点击率通常靠封面单独撑。

**封面与标题的关系**（关键观察点，三选一）

- **互补型**：封面给情绪，标题给方法（最常见，最稳）
- **重复型**：封面照抄标题（浪费一次曝光机会）
- **反差型**：封面制造疑问，标题给出方向（上限高，风险也高）

### 1.2 正文钩子

小红书正文有**折叠线**（约前 3 行），这 3 行决定用户是否点「展开」。

**首句钩子类型**

| 类型 | 模板 | 例 |
|---|---|---|
| 痛点共鸣 | 是不是也…… | 是不是也每次写周报都拖到周五晚上 |
| 反常识 | 别再……了 | 别再背单词了，我试了 3 个月没用 |
| 结果前置 | 我……了 | 我把每周 5 小时的对账压到 20 分钟 |
| 身份代入 | 作为…… | 作为做了 8 年 HR，我必须说 |
| 成本量化 | 只花了…… | 只花了 30 块，家里像换了套 |

**正文标准骨架**（多数拆解对象都落在这个形状上）

```
钩子（1-2 句）
  → 信任状 / 背景（为什么听我的，1-2 句，可省略）
  → 干货分点（3-6 点，emoji 或符号做分隔）
  → 每点 = 结论 + 一句话理由（小红书不展开长篇论证）
  → 效果 / 对比 / 截图佐证
  → 互动引导
```

**节奏特征**：段短（1-3 句）、句子短、视觉留白多、emoji 当分隔符而非装饰。

### 1.3 互动引导

| CTA 类型 | 话术 | 目的 |
|---|---|---|
| 收藏 | 建议收藏 / 先码住 | 提高收藏权重 |
| 关注 | 关注不迷路 / 蹲后续 | 转化粉丝 |
| 评论关键词 | 评论区扣 1 / 想要的说一声 | 拉评论量 |
| 提问式 | 你们都用什么方法？ | 拉评论量（最自然） |
| 私信 | 需要模板的私信我 | 引流 |

**拆解要点**：CTA 放在哪一句？是硬求还是包在内容里（「我整理成表了，需要的说一声」）？
后者转化通常更高，因为它把 CTA 变成了内容的一部分。

### 1.4 标签

`#话题` 通常 3–8 个，拆解时记录：是否混用大词（泛流量）+ 小词（精准流量）。

## 2. 公众号 · 开篇引入法 → 小标题逻辑链 → 金句收尾

公众号是**订阅制 + 打开率**驱动的长图文。用户已经点进来了，所以开篇的任务不是
「吸引点击」，而是**阻止退出**——前两段必须建立「这跟我有关」。

### 2.1 开篇引入法

| 引入法 | 手法 | 适合 |
|---|---|---|
| 故事型 | 一个具体的人、时间、场景 | 观点文、情感文 |
| 新闻由头 | 近期事件切入 | 热点评论 |
| 提问型 | 直接抛一个读者正在想的问题 | 干货、方法论 |
| 数据型 | 一个反直觉的数字 | 商业、行业分析 |
| 场景白描 | 描述读者经历过的画面 | 共鸣型 |
| 反常识断言 | 直接否定一个常识 | 观点输出（风险高、传播强） |

**拆解要点**：记下「第几段完成从引入到立论」的过渡。优秀的开篇通常在第 **3–5 段**
内完成过渡，拖到第 8 段之后打开率会明显掉。

### 2.2 小标题逻辑链

小标题不是分段装饰，是**逻辑链的可视化**。拆解时必须判定它属于哪一类：

| 逻辑链 | 形状 | 读者预期 |
|---|---|---|
| 并列 | A / B / C 三件事 | 我会得到一份清单 |
| 递进 | 是什么 → 为什么 → 怎么做 | 我会被层层推进 |
| 对比 | 旧方法 vs 新方法 | 我会看到差距 |
| 时间线 | 之前 / 之后 | 我会看到一个过程 |
| 总分 | 先说结论，再拆支点 | 我会先拿结论再看论证 |
| 破立 | 先驳倒常见做法，再给新做法 | 我会被说服 |

**节奏数据**：记录小标题之间的段落数/字数。常见节奏是每 **300–600 字**一个小标题；
间隔超过 1000 字，长文会失去牵引感。

**拆解要点**：小标题本身是否可独立阅读（只看小标题能否读懂全文脉络）？
能，说明逻辑链做得好。

### 2.3 金句收尾

**收尾类型**

| 类型 | 手法 |
|---|---|
| 回扣开头 | 把开篇的故事/问题收回来 |
| 升华 | 从小事引到大道理（易沦为套话，注意分辨） |
| 行动号召 | 给一个明确的下一步 |
| 留白提问 | 把问题交还读者，拉评论 |
| 金句定格 | 用一句话锁住全文结论 |

**金句的可识别特征**：短（≤25 字）、有对仗或转折、能脱离上下文独立传播、
常被截图转发。拆解时把候选金句**原样摘出并标位置**。

## 3. 知乎 · 问题定义 → 论证结构 → 情绪落点

知乎是**问答场**，用户的默认心理是「我在找一个可信的答案」。因此它的爆款逻辑
和公众号相反：**不是靠情绪开场，而是靠专业感留人，靠情绪收尾。**

### 3.1 问题定义

知乎高赞的第一动作常常不是回答，而是**重新定义问题**：

| 手法 | 说明 | 例 |
|---|---|---|
| 收窄问题 | 把大问题变成可答的小问题 | 「你问的是技术问题还是人的问题？」 |
| 否定前提 | 指出问题问错了 | 「这个问题问反了，真正的问题是……」 |
| 拆成两层 | 表面问题 vs 实际问题 | 「你想知道怎么选，其实是怕选错」 |
| 补足条件 | 加限定条件才有答案 | 「取决于你的团队是 5 人还是 50 人」 |

**拆解要点**：第一段有没有建立「我比提问者更懂这个问题」的位置？靠什么建立
（身份、数据、反直觉判断）？

### 3.2 论证结构

| 结构 | 形状 | 信任来源 |
|---|---|---|
| 先结论后论证 | 第一段就给答案 | 敢下判断 |
| 悬念推进 | 铺垫 → 转折 → 揭晓 | 阅读体验 |
| 第一性原理拆解 | 拆到最基本的事实再推 | 逻辑深度 |
| 正反对照 | 列两种做法各自代价 | 全面性 |
| 案例驱动 | 讲 2–3 个真实案例再归纳 | 实证感 |
| 分层作答 | 分「短期 / 长期」「个人 / 组织」 | 结构化 |

**信任状（Trust Signal）**：知乎读者对作者身份高度敏感。拆解时必须记下
信任状出现在第几段、以什么形式出现（「我在这个行业做了 8 年」/ 贴数据 / 出示作品）。

**拆解要点**：论证中是否包含**可被反驳的具体主张**？全是正确废话的回答拿不到高赞。

### 3.3 情绪落点

知乎高赞常见落点：

| 落点 | 读者感受 |
|---|---|
| 被理解 | 「原来不是我的问题」 |
| 认知升级 | 「原来是这样，我以前想错了」 |
| 认同感 | 「说出了我想说的」 |
| 愤慨 | 「这确实不合理」 |
| 释然 | 「不必焦虑了」 |

**拆解要点**：情绪落点通常放在最后 1–2 段，且常以一句金句或一个反问结束。
记下这一句，它是评论区的引爆点。

## 4. 视频号 · 前 3 秒钩子 → 结构节奏 → 结尾引导

| 层 | 观察点 |
|---|---|
| 前 3 秒钩子 | 口播钩子（第一句话）／画面钩子（视觉冲击）／文字钩子（贴片字幕）。三者至少一个要强 |
| 结构节奏 | 单点突破型（一件事讲透）／清单型（3 点）／故事型。信息点间隔通常 5–8 秒 |
| 结尾引导 | 关注 / 点赞 / 评论 / 转发四选一，**只放一个**（多个会互相稀释） |
| 社交分发 | 视频号依赖社交推荐，所以结尾常带「转发给需要的朋友」式话术 |

**拆解要点**：记下第一句话的**原始文本**，这是全片最重要的一句。
并判断它是「结论前置」还是「悬念前置」。

## 5. 抖音 / 快手 · 3 秒钩子 → 完播结构 → 互动引导

| 层 | 观察点 |
|---|---|
| 3 秒钩子 | 冲突／悬念／视觉奇观／身份宣言。抖音前 3 秒决定 80% 的流失 |
| 完播结构 | 前置高潮（把最刺激的放最前）／信息密度拉满（不留空拍）／中途反转 |
| 互动引导 | 评论区提问（拉评论）／「你选哪个」（拉互动）／结尾留钩（拉复看） |

**拆解要点**：找出「反悔点」——观众原本想划走、但被什么留住了？这是可复用的关键。

## 6. B站 · 标题封面 → 开场承诺 → 章节推进 → 三连引导

| 层 | 观察点 |
|---|---|
| 标题封面 | 标题给「信息增量」，封面给「话题性」，常配合提问式标题 |
| 开场承诺 | 前 15 秒说明「本期讲什么、你能得到什么、为什么可信」 |
| 章节推进 | 有明确分段感（章节、进度提示、小结），适合中长视频 |
| 三连引导 | 放在内容价值峰值之后，而非结尾硬讨 |

**拆解要点**：B站观众的容忍度高但要求回报高。拆解时注意「承诺」与「兑现」的
对应关系——开场承诺的 3 件事，是否都有对应段落兑现。

---

## 7. 微博 · 热点锚点 → 观点爆点 → 转发话术

| 层 | 观察点 |
|---|---|
| 热点锚点 | 是否挂着当前热点（借势），以及挂得自然还是生硬 |
| 观点爆点 | 一句可引用的态度句，通常带立场、带争议 |
| 转发话术 | 让转发者「显得有态度」——这是微博转发的真实动机 |

**拆解要点**：微博爆款的单位不是「文章」，是**那一句话**。拆解时把这句话单独摘出来。

---

## 8. 播客 / 长音频 · 开场承诺 → 话题分段 → 结尾钩子

| 层 | 观察点 |
|---|---|
| 开场承诺 | 前 2 分钟说明本期主题与收听理由（播客没有画面，全靠承诺留人） |
| 话题分段 | 有明显的话题切换信号（「接下来说说……」「我们换个话题」） |
| 结尾钩子 | 下期预告／金句回扣／行动建议 |

## 9. 跨平台通用模式库

### 9.1 钩子类型速查（12 种，任何平台可用）

`提问型` `反常识` `结果前置` `痛点共鸣` `身份代入` `数字清单`
`成本量化` `冲突悬念` `故事开场` `场景白描` `权威引用` `利益承诺`

拆解时从中选一个命名，**不要用「吸引人的开头」这种描述**。

### 9.2 结构原型速查（12 种通用骨架）

`总分总` `递进式` `并列清单` `正反对照` `时间线` `破立式`
`问题-方案` `案例归纳` `第一性原理拆解` `故事-道理` `场景-方法-效果` `悬念揭晓`

### 9.3 CTA 类型速查（脚本可自动检出）

`收藏型` `关注型` `评论关键词` `提问式` `转发型` `私信引流型` `点赞型` `三连型` `在看型`

> 多于 2 种并存会互相稀释转化，通常只保留一种最好。

### 9.4 情绪手法速查（需模型读文判定）

`共鸣（说出读者的处境）` `认知反差（颠覆预期）` `身份认同（我们这类人）`
`紧迫感（错过就没了）` `释然（不必焦虑）` `愤慨（这不合理）` `好奇缺口（答案在后面）`

> 说明：9.1 钩子类型与 9.3 CTA 类型由 `scripts/decode_scan.py` 自动检出；
> 9.2 结构原型与 9.4 情绪手法依赖语义判断，**必须由模型读原文后判定**，
> 脚本不会给结论。判定时一律使用本节的标准名称，不要自造描述。

## 10. 新增平台的扩展模板

遇到未覆盖的平台时，按这 4 个问题现场推导框架，并把结果追加到本文件（保持两级目录）：

1. **分发机制**：内容怎么被看到？（搜索 / 关注 / 算法推荐 / 社交转发）
   → 决定第一层的决策点是什么
2. **用户决策点**：用户在哪一步决定留下？（点开 / 3 秒 / 折叠线 / 读完前 3 段）
   → 决定 L1 注意力层的位置与强度要求
3. **内容形态**：图文 / 短视频 / 长视频 / 音频 / 问答
   → 决定 L3 主体层的组织方式与节奏尺度
4. **成功指标**：平台奖励什么行为？（完播 / 收藏 / 转发 / 评论 / 停留时长）
   → 决定 L5 引导层的 CTA 类型

### 推导示例

> **平台**：某个以搜索为主要流量来源的知识社区
> **分发机制**：搜索为主 → 标题必须匹配用户的搜索措辞，而非追求点击欲望
> **用户决策点**：搜索结果页的标题+摘要
> **内容形态**：长图文
> **成功指标**：收藏、采纳、长停留
> **推出框架**：搜索词匹配度 → 首段直接给答案 → 分层论证 → 收藏引导
> **与公众号的差异**：开篇不需要「引入」，需要「立刻给结论」，因为用户带着明确问题进来的
